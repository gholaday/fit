# Decisions

Running log of decisions that change or clarify the spec.

| Date | Decision | Why |
|---|---|---|
| 2026-10-26 | Expo SDK 58 (RN 0.88, React 19.3, Reanimated 4.7, New Architecture only). | Current stable SDK. |
| 2026-10-26 | Styling uses React Native `StyleSheet` with a typed token module, not NativeWind. | NativeWind 4 (stable) targets Tailwind 3 and has friction with Reanimated 4; NativeWind 5 is still RC. StyleSheet has zero runtime cost. |
| 2026-10-26 | TypeScript pinned to 6.0.x. | typescript-eslint does not support TS 7 yet. |
| 2026-10-26 | pnpm `node-linker=hoisted`. | Metro and Expo autolinking are most reliable with a hoisted layout. |
| 2026-10-26 | API stays a stub in M0; real sync lands in M2.5. | Per handoff. |
| 2026-10-26 | Strength workouts are not hard days for back-to-back warnings. | Answers spec open question 6. |
| 2026-10-26 | Units default to miles and pounds, setting to switch. HR zones default to Karvonen. Maps will use MapLibre. | Handoff defaults. Internally everything is stored in meters, seconds and kg. |
| 2026-10-26 | `weekly_schedule` gains `starts_on` / `ends_on`. "Change the schedule" and weekday edits end the old entry and start a new one. | Past weeks and their completions keep their original days. |
| 2026-10-26 | DSL: bare `m` below 100 means minutes ("10m easy"), 100 and up means meters ("800m"). `min`, `km`, `mi` are explicit. | Matches how the spec's templates are written while staying unambiguous in practice. |
| 2026-10-26 | Plan workouts store pace zones, not resolved paces. A 5K goal time creates a `pace_profiles` row (`source = goal`). | A later VDOT bump updates every future workout without regenerating the plan. |
| 2026-10-26 | Migrations are inlined into `packages/schema/src/migrations.ts` by `pnpm --filter @fit/schema db:generate`. | Metro needs no `.sql` loader. |
| 2026-10-26 | Voice cues duck music through a small local Expo module (`apps/mobile/modules/audio-focus`) that requests `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` around each cue. | expo-speech never requests audio focus, and expo-audio only ducks while its own player plays. The spec requires ducking. |
| 2026-10-26 | The run notification uses expo-location's SDK 58 `BackgroundSession` API, with title "Run in progress" and text "2.41 mi, 21:14", updated on each location batch. | The legacy `startLocationUpdatesAsync` can't update notification text without restarting updates (risking gaps). An Android notification has only one text line. |
| 2026-10-26 | Maps use `@maplibre/maplibre-react-native` 11.5 with OpenFreeMap tiles (no key). It's unverified on RN 0.88 until the first native build. | Spec preference; resolves open question 4. |
| 2026-10-26 | Background location uses the SDK 58 `AUTOMOTIVE_NAVIGATION` profile. | It's the only profile with 1 s fixes and no batching or distance filter, which spec §5 needs. `FITNESS` is a 10 s interval with 2-minute batches. |
| 2026-10-26 | Countdown beeps are spoken ("Three", "Two", "One") through the same audio-focus path instead of using expo-audio. | expo-audio's plugin adds RECORD_AUDIO and a playback service by default. Spoken counts duck music with no extra package or permission. |
| 2026-10-26 | Player state records pause ranges; Settings gains `voice`, `cues`, `autoPause`, `autoPauseOnWalks`. | Splits exclude paused time and replay marks gaps; cue preferences persist (spec §5, §16). |
| 2026-10-26 | The exercise catalog ships as bundled `catalog.json`, upserted in one transaction (about 200 ms) after first paint, only when `CATALOG_VERSION` changes. Not a prebuilt SQLite file. | Spec §2 says prebuilt SQLite and §9 says JSON. JSON keeps one database file, lets seeding preserve hidden flags and custom rows, and never touches startup. |
| 2026-10-26 | Thumbnails (192 px WebP) ship for every exercise and detail frames (720 px) for stretches only, about 7 MB total. No Vercel Blob for now. | The guided player works fully offline; strength detail images can move to Blob later. Answers open question 8 for v1. |
| 2026-10-26 | Starter routines are read-only and re-seeded in place by slug; editing means "Duplicate". M0 starter rows are upgraded by name, keeping schedule links. | Re-seeding can never clobber your edits. |
| 2026-10-26 | Exercise names are sentence case with " - " turned into ", ", via overrides plus automatic cleanup. | Copy rules (no dashes as separators, sentence case). |
| 2026-10-26 | No exercise images in the app (user decision). The stretch player shows the move's instructions in large type under the countdown; rows are text only. The image assets, the `./images` export and sharp are removed once mobile stops using them. | The source images aren't good enough to show. It also saves about 7 MB in the APK. Supersedes the thumbnail row above. |
| 2026-10-26 | M2 data: `hr_samples` keyed by (session, source, offset); live BLE samples are written with `saveProgress`, Health Connect samples only fill live dropouts longer than 5 s (`mergeHr`). `external_sessions.status` is new, saved, merged or ignored ("new" is the spec's "imported", waiting in the modal). Completions gain `external_session_id` so watch-only runs count as Done + data. | One HR trace per session with the source kept; the modal's state lives on the row, and Later simply leaves it "new". |
| 2026-10-26 | Health Connect reads stay in the app; the repository takes normalized records (`importExternalSessions`, `addHealthHr`, `upsertDailyMetrics`) and owns merge, match and dedupe by `hc_record_id`. Only Garmin Connect records are imported unless "All sources" is on. | Keeps the native library out of `packages/*` and the rules testable in Node. |
| 2026-10-26 | Live HR uses a local Expo module (`apps/mobile/modules/hr-sensor`, Kotlin) instead of `react-native-ble-plx`: scan for service 0x180D, subscribe to 0x2A37, emit raw bytes with a native timestamp; `@fit/core` parses them. Health Connect uses `react-native-health-connect` 4.1.3 with its own config plugin; minSdk goes to 26. | Spec §7 names ble-plx, but it is an old-architecture bridge on RxJava2, tested only to RN 0.77. A small native module has no dependency and keeps the GATT connection alive under the run's foreground service. connect-client 1.1.0 needs minSdk 26. |
| 2026-10-26 | Icons switch from Tabler to Phosphor (`phosphor-react-native`): regular weight, filled glyphs on activity tiles in the lane color (user decision). | The user found the Tabler activity icons weak. One mapping file in the app keeps the swap contained. |
| 2026-10-26 | Neon sync moves from M2.5 to M11 (user decision). After M2 comes M3. | The app is local-first and fully usable without it. Every synced table already carries updated_at, deleted_at and dirty, so sync can be added later without migrations of existing data. |
| 2026-10-26 | M3 treadmill distance comes from the speed you set in the app (± 0.1 / ± 0.5), integrated over active time; each step suggests a speed from its pace zone's target pace. Settings remember easy and walk speeds. "Treadmill says X km" and Timer's manual distance both use `correctDistance`, which rescales step distances. | Spec §5. One correction path for both modes. |
| 2026-10-26 | Route import is GPX only for now (`parseGpx`, with Garmin HR extensions); FIT import waits. Free runs get a sentence-case auto title ("Tuesday intervals"). | GPX is plain text and Garmin Connect exports it; FIT is a binary format that needs a parser. Copy rules use sentence case, unlike the spec's "Tuesday Intervals" example. |
| 2026-10-26 | Icons switch again, from Phosphor to Lucide drawings in `apps/mobile/src/ui/icons.tsx` with react-native-svg, no package (user decision, matching murmur). Supersedes the Phosphor entry above. | The user preferred murmur's look. Lucide is ISC licensed; the notice is in the file. |
| 2026-10-26 | M5: built-in 1 mile, 3 km and 5 km time trials (trial step labeled "Time trial"); a saved session's trial result uses the planned distance and recorded time, and updates paces only when you accept. The +1 VDOT prompt counts sessions since the current profile and the last dismissal. The beginner fallback ("Can you run 20 min?", effort-only plans) moves to M6 with the plan engine. | Spec §6. Distance steps end when GPS reaches the distance, so the planned distance is the accurate one. The fallback changes plan generation, which is M6 work. |
| 2026-10-26 | M6 presets: 10K, Half Marathon, Couch to 5K, Walk to Run, Base Builder (4, 8 or 12 weeks), Speed Block, Zone 2 Run/Walk Start, Zone 2 Walk (4, 8 or 12 weeks) and Zone 2 + Speed join 5K and Zone 2 Base. Wizard pace source: race (recent race), trial (3 km time trial in week 1) or beginner (pace targets become effort). "Can you run 20 minutes?" suggests run/walk plans when the answer is no. | Spec §7 and §8 preset tables. Base Builder's open-ended cycles are offered as fixed lengths; regenerate for another block. |
| 2026-10-26 | Hard days come from content: long runs always, other hard roles only with hard steps (`isHardWorkout`). Day selection breaks ties by fewer back-to-back pairs. | A Zone 2 aerobic test is easy (spec §7). With 4+ days chosen from all 7, the old smallest-gap rule tied every option and packed Monday to Wednesday. |
| 2026-10-26 | M6 adaptation runs in `adaptPlan` (core) and `repository.adaptPlan` (at most once a day per plan, or forced after a save or move). Dropped workouts get status `missed` and show as skipped. A missed whole week repeats in fitness plans (the plan ends a week later); race plans drop it and lighten the next week by 20%. Two or more missed weeks ask "Rebuild plan from here?". The easy-run RPE check only suggests slowing down: the pace profile has no per-zone override for "-1 VDOT for easy only". | Spec §8 adaptation rules. Race dates cannot move, so race plans cannot repeat a week. |
| 2026-10-26 | SQLite runs with WAL and `synchronous = NORMAL` (user decision, from the performance pass). Write transactions went from 2 to 3.6 ms down to about 0.4 ms. | An app crash cannot lose data; a power loss or OS crash can lose the last few writes, which is acceptable for a training log with 5 s run saves. |
| 2026-10-26 | M9 stats: each saved run stores `SessionStats` in `sessions.stats_json` at finish (distance by run, walk and sprint steps, easy running distance and time, best efforts). Runs saved before 0.4.0 get theirs on the first `runRows` or `personalBests` call. Sessions gain `kind` ('run' or 'strength'), backfilled from the strength summary. | Stats over months stay a single indexed query with no track reads, which keeps Stats instant (spec §2 performance). |
| 2026-10-26 | Personal bests come from outdoor Fit runs only (sliding window over the track, paused time excluded). Treadmill and imported sessions count toward totals but not bests. Pace at Zone 2, decoupling and run/walk ratio trends move to M10 with the other heart rate work. | Treadmill distance is a calibration estimate and watch imports have no track here, so neither is reliable for a best effort. |
| 2026-10-26 | M10 HR cues live in `cuesFor` (hr input and `hrRange` context): "Ease off" after 20 s above the range (at most once a minute), "Back in zone two" with a soft `zone` haptic only after an alert, optional "pick it up" below (60 s) and 5 minute zone updates. New cue prefs `hrAlerts` (on), `hrBelow` and `zoneUpdates` (off). `settings()` now merges object settings over their defaults, so older saved cue prefs pick up new fields. | Spec §7 in-session cues; hysteresis keeps them from nagging. |
| 2026-10-26 | HR-driven run/walk: steps with `hrGuard.walkWhenAbove` switch phases via `runWalkPhase` (walk at the cap, run again 10 bpm below, 20 s minimum per phase, a dropout keeps the phase). Phases are a `phase` player event and live in `PlayerState.runWalk`, so they persist with crash recovery and count walk phases as walking in stats. HR alerts are silent on these steps; the walk break is the cue. | The phase log has to survive a restart and feed the run/walk ratio trend. |
| 2026-10-26 | HR progress lives in `SessionStats` v2: Zone 2 seconds, outdoor distance and time while in Zone 2, decoupling of the longest easy run step when 40 min or more, and run/walk seconds. Stats are recomputed when the version changes or Health Connect HR is added or undone. Treadmill runs count toward Zone 2 minutes but not the pace at Zone 2 trend. | Pace at Zone 2 needs a track; treadmill pace comes from a calibration estimate. |
| 2026-10-26 | Personal records (user request, Hevy-style). Runs: fastest 1 km, 1 mi, 5 km, 10 km and half; longest run by distance and by time; longest non-stop run; biggest week; firsts (5 km, 10 km, half, first hour). Lifts per exercise: heaviest weight, estimated 1 rep max (Epley, sets of 12 reps or fewer), best set volume, most reps (bodyweight), longest hold, best session volume. Speed and distance only, no HR records (user decision). The first value of a record is kept quietly; improvements and firsts get a trophy and a small pop-up (user decision). Non-stop only celebrates on runs that included walking. Watch runs count for distance and time records, not efforts. | Records are derived by `computeRecords` from saved runs and sets and cached in memory, so deletes and edits can never leave a stale record and no table or sync is needed. |
| 2026-10-26 | Run days change in place (`changeRunDays`): upcoming runs move to their role's new weekday inside the same planned week, never into the past; a retest follows the quality day. Same runs per week; changing that still rebuilds. `weekKind` and `PresetInfo.cutbackEvery`/`taperWeeks` label cutback and taper weeks. GPX export (`toGpx`) and expo-sharing are removed with the export buttons (user decision); GPX import stays. | Keeps completed history and week alignment, which a rebuild from today would reset. |
| 2026-10-26 | The Today widget becomes a day ring (user decision): an inner ring with one arc per lane scheduled today in equal shares, each filling by the share of its items done, and an outer steps ring. Tapping an arc or the steps ring switches the details panel beside it; the item strip leaves the widget and stays on the slim bar. Shares and hit testing are `dayRing` and `ringHit` in core. The app icon follows this ring. | A ring that shows the real day makes the icon honest, and equal lane shares stay readable whatever the item count. |
| 2026-10-26 | The Today widget settles on one gapless day ring with a This week panel of small day rings, and steps move to their own card with an hourly line read from Health Connect on demand (user decision). Supersedes the two-ring entry above. Weight tracking is specced in §12 (user answers): manual and Health Connect weigh-ins, a smoothed trend leads every number, one goal of target and weekly pace set from Plan, a quick weigh-in on Today. | Hourly steps are cheap to aggregate and change all day, so storing them adds sync work for nothing. A trend is the honest weight number; daily weights swing with water. |
| 2026-10-26 | Weight data: `weigh_ins` and `weight_goals` tables (migration 0005). Health Connect weights import from every app, not only Garmin Connect, because scales write their own records. The weekly rate fits the raw daily weigh-ins; the trend is for display. A goal is marked reached on the write that crosses the target and stays reached; `weightGoal()` returns it until a new goal is set. | Scale apps are the main source of weight records. A 7 day trend under-reads a steady loss by about a third two weeks in. |
